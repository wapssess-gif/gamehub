# Открытые вопросы

Уже решено (см. также [README.md](README.md)):

- Источник данных об играх: **RAWG** (решение зафиксировано в
  [05-architecture.md](05-architecture.md), 2026-09-04).
- Масштаб: pet/учебный проект.
- Платформа: только веб, адаптивная вёрстка.
- Стек: **Next.js + PostgreSQL + Prisma + NextAuth** (Вариант A из
  [05-architecture.md](05-architecture.md), решение зафиксировано
  2026-09-04).

Ниже — вопросы, которые пока не закрыты и стоит решить по мере того,
как документация переходит в реализацию.

## Продукт

1. **Название и брендинг.** "GameHub" использован как рабочее название
   в этой документации — финальное имя, домен, визуальный стиль не
   выбраны.
2. **Язык интерфейса.** Русский, английский или оба сразу (i18n)?
   Влияет на структуру строк с самого начала.
3. **Монетизация.** Проект бесплатный без всякой монетизации, или
   в будущем возможна донат-модель / реклама / подписка? Даже если
   ответ "пока никак", лучше зафиксировать, чтобы не блокировать
   архитектуру задним числом.
4. **Модерация контента.** Отзывы и скриншоты — пользовательский
   контент. Нужна ли (хотя бы в перспективе) система жалоб/банов, или
   на этапе pet-проекта достаточно ручного вмешательства автора?

## Данные и интеграции

5. **Достижения (F11).** Нужно проверить, отдаёт ли выбранное API
   ачивки по играм в принципе (у RAWG их нет; у IGDB есть частично
   через связанные сущности) — это может понизить приоритет F11 до C
   или сделать его невозможным без Steam Web API как доп. источника.
6. **Импорт существующих библиотек.** Стоит ли на будущем этапе дать
   пользователям импортировать библиотеку из Steam/Xbox/PSN, чтобы не
   вбивать всё вручную? Не в MVP, но влияет на модель `UserGame`
   (нужно ли поле `imported_from`).

## Дизайн и UX

7. **Референсы визуального стиля.** Есть ли сайты/приложения, чей
   внешний вид или UX нравится (например, Letterboxd для отзывов,
   HowLongToBeat для трекинга, Steam для каталога)? Поможет задать
   направление до перехода к макетам.
8. **Тёмная/светлая тема.** Геймерская аудитория часто ожидает тёмную
   тему по умолчанию — подтвердить приоритет.

## Инфраструктура

9. **Бюджет на хостинг/сервисы.** Даже бесплатные тарифы (Vercel,
    Supabase, RAWG API) имеют лимиты — окей ли это для pet-проекта,
    или сразу закладываемся на платные тарифы при росте нагрузки?
10. **Домен.** Будет ли куплен собственный домен, или на первое время
    достаточно поддомена хостинга (`*.vercel.app` и т.п.)?

## Как использовать этот список

Это не блокер для старта разработки MVP — стек и внешнее API уже
выбраны. Большинство оставшихся пунктов относятся к этапам 2–3 из
[06-roadmap.md](06-roadmap.md) или к деталям, которые можно решить
"по умолчанию" (например, тёмная тема по умолчанию, русский язык
интерфейса) и поменять позже. Стоит явно проговорить перед тем, как
приступать к разработке, вопросы 1–4 (продукт) — они сильнее всего
влияют на структуру MVP (i18n, схема модерации).
