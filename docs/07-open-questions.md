# Открытые вопросы

Уже решено (см. также [README.md](README.md)):

- Источник данных об играх: **RAWG** (решение зафиксировано в
  [05-architecture.md](05-architecture.md), 2026-09-04).
- Масштаб: pet/учебный проект.
- Платформа: только веб, адаптивная вёрстка.
- Стек: **Next.js + PostgreSQL + Prisma + NextAuth** (Вариант A из
  [05-architecture.md](05-architecture.md), решение зафиксировано
  2026-09-04).
- Язык интерфейса: **русский и английский**, переключатель RU/EN в
  шапке сайта (реализовано 2026-09-04). Локаль хранится в cookie,
  переводы — в `src/i18n/dictionaries.ts`. Названия жанров/платформ из
  RAWG остаются на английском независимо от локали — сам RAWG их не
  переводит, это ограничение источника данных, а не UI.
- Тёмная/светлая тема: **только тёмная тема** (решение 2026-09-06).
  Изначально цвета следовали `prefers-color-scheme`, но светлая тема
  требовала поддержки двойного набора классов в каждом компоненте и
  давала баги с контрастом текста — для pet-проекта не оправдано.
  Сейчас `globals.css` задаёт единственную тёмную палитру, переключателя
  и light-варианта в UI нет.

Ниже — вопросы, которые пока не закрыты и стоит решить по мере того,
как документация переходит в реализацию.

## Продукт

1. **Название и брендинг.** "GameHub" использован как рабочее название
   в этой документации и в коде (заголовок, метаданные) — финальное
   имя, домен, визуальный стиль не выбраны.
2. **Монетизация.** Проект бесплатный без всякой монетизации, или
   в будущем возможна донат-модель / реклама / подписка? Даже если
   ответ "пока никак", лучше зафиксировать, чтобы не блокировать
   архитектуру задним числом.
3. **Модерация контента.** Отзывы и скриншоты — пользовательский
   контент. Нужна ли (хотя бы в перспективе) система жалоб/банов, или
   на этапе pet-проекта достаточно ручного вмешательства автора?

## Данные и интеграции

4. **Достижения (F11).** Нужно проверить, отдаёт ли выбранное API
   ачивки по играм в принципе (у RAWG их нет; у IGDB есть частично
   через связанные сущности) — это может понизить приоритет F11 до C
   или сделать его невозможным без Steam Web API как доп. источника.
5. **Импорт существующих библиотек.** Стоит ли на будущем этапе дать
   пользователям импортировать библиотеку из Steam/Xbox/PSN, чтобы не
   вбивать всё вручную? Не в MVP, но влияет на модель `UserGame`
   (нужно ли поле `imported_from`).

## Дизайн и UX

6. **Референсы визуального стиля.** Есть ли сайты/приложения, чей
   внешний вид или UX нравится (например, Letterboxd для отзывов,
   HowLongToBeat для трекинга, Steam для каталога)? Текущий UI —
   минимальная функциональная вёрстка на Tailwind без проработанного
   дизайна; поможет задать направление до следующего визуального прохода.

## Инфраструктура

7. **Бюджет на хостинг/сервисы.** Даже бесплатные тарифы (Vercel,
   Supabase/Neon, RAWG API) имеют лимиты — окей ли это для pet-проекта,
   или сразу закладываемся на платные тарифы при росте нагрузки?
   Сейчас проект развёрнут только локально (локальный PostgreSQL),
   хостинг не выбран.
8. **Домен.** Будет ли куплен собственный домен, или на первое время
   достаточно поддомена хостинга (`*.vercel.app` и т.п.)?
9. **CI.** Базовый CI (lint + build на пуш/PR) пока не настроен —
   стоит добавить перед тем, как в проекте появится больше одного
   разработчика или веток.

## Как использовать этот список

Это не блокер для дальнейшей разработки — MVP (Этап 1) уже реализован
без ответов на большинство этих пунктов. Вопросы 1–3 (продукт) стоит
явно проговорить перед началом Этапа 2 (социальный слой) — они сильнее
всего влияют на его архитектуру (i18n при масштабировании, схема
модерации для отзывов).
