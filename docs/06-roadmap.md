## Этап 1 — MVP (функции M) ✅ (2026-09-04)

Цель: пользователь может завести аккаунт, найти игру, добавить в
библиотеку, отслеживать прогресс и видеть статистику.

- [x] Регистрация/вход (email + пароль) — F1
- [x] Личный профиль (ник, био, загрузка аватара) — F3
      Аватары хранятся в Vercel Blob (`BLOB_READ_WRITE_TOKEN`); изображение
      уменьшается до 256×256 на клиенте перед загрузкой. Без токена загрузка
      аватара отключается, профиль показывает инициалы.
- [x] Поиск игр через внешнее API + кэш в `Game` — F5
- [x] Добавление в библиотеку со статусом — F6
- [x] Прогресс (% / часы) — F7. Также сохраняются приватные заметки
      (`UserGame.notes`) и авто-даты `startedAt` / `finishedAt` при смене
      статуса на «играю» / «пройдено».
- [x] Оценка игры — F8
- [x] Статистика аккаунта — F9
- [x] Каталог/поиск с фильтрами по жанру/платформе — F18.
      Страница игры (`/games/[id]`) тянет из RAWG расширенные данные:
      оценка Metacritic, рейтинг сообщества, разработчик/издатель, ESRB,
      среднее время прохождения, сайт, описание и галерею скриншотов
      (эндпоинт `/games/{id}/screenshots`, до 6 штук).

Реализация: см. [корневой README](../README.md) для запуска и списка
файлов. Критерий готовности этапа — см. "Definition of Done" в
[03-user-stories.md](03-user-stories.md) — выполнен и проверен вручную
end-to-end, включая поиск/добавление игр через реальный RAWG API
(регистрация → авто-вход → библиотека → поиск игры → добавление →
смена статуса/прогресса/оценки → пересчёт статистики; выход, редирект
неавторизованных). Функции F10, F17 и т.д. — вне MVP, см. Этапы 2–3
ниже.

Сверх исходного списка M-функций также добавлен переключатель языка
интерфейса RU/EN (см. [07-open-questions.md](07-open-questions.md)) —
не было в исходных требованиях, но не блокирует их и упрощает
дальнейшую демонстрацию проекта.

По UI: интерфейс только в тёмной теме (решение 2026-09-06, см.
[07-open-questions.md](07-open-questions.md)); попытка машинного перевода
описаний игр из RAWG откатана как нерабочая — жанры/платформы/описания
остаются на языке источника.

## Этап 2 — Социальный слой (функции S)

Из S-функций осталось: OAuth Steam (часть F2) и топы/подборки по рейтингу
комьюнити (F20).

- [x] OAuth-вход — Google (F2, частично) (2026-09-07)
      Кнопка «Продолжить через Google» на `/login` и `/register`,
      включается переменными `AUTH_GOOGLE_ID/SECRET` (как
      `BLOB_READ_WRITE_TOKEN`). JWT-сессии без адаптера БД; аккаунт
      создаётся/привязывается по подтверждённому Google-email в
      `signIn`-колбэке ([src/auth.ts](../../../GAMEHUB/src/auth.ts)).
      Новому пользователю выдаётся временный ник и `User.onboardedAt = null`;
      экран `/onboarding` (гейт в middleware) заставляет выбрать `@ник`.
      **Steam** отложен: у NextAuth v5 нет провайдера (OpenID 2.0), Steam
      не отдаёт email — потребует таблицу `Account` и nullable `email`.
- [x] Друзья (запрос/принятие) + односторонние подписки — F13
      Поиск пользователей на `/users` — по `@нику`, имени (`displayName`)
      или короткому ID (`User.publicId`, автоинкремент, в UI с ведущими
      нулями до 10 знаков). Публичные профили `/u/[username]` (или
      `/u/<publicId>`) с библиотекой и статистикой, хаб связей `/friends`.
      Модели `Follow` / `Friendship` в [prisma/schema.prisma](../prisma/schema.prisma).
- [x] Приватность профиля (базовый флаг PUBLIC/PRIVATE) — F4 (частично)
      Приватный профиль скрывает библиотеку и статистику от всех, кроме
      принятых друзей. Уровень «только друзья» как отдельный режим — позже.
- [x] Коллекции игр — F10 (2026-09-06)
      Пользовательские подборки: создание/редактирование/удаление коллекции
      (`/collections`, `/collections/new`, `/collections/[id]`), добавление игр
      из своей библиотеки. Модели `Collection` / `CollectionItem` в
      [prisma/schema.prisma](../prisma/schema.prisma), server actions в
      `src/lib/actions/collections.ts`. Флаг `isPublic` в схеме есть, но
      отдельной страницы публичной коллекции пока нет — все коллекции видны
      только владельцу.
- [x] Лента активности друзей — F14 (2026-09-06)
      Страница `/feed`: события «добавил в библиотеку / начал играть /
      прошёл / оценил» от друзей и подписок, свежие сверху. Модель
      `ActivityEvent` (данные об игре денормализованы в `payload`),
      события пишутся из `src/lib/actions/library.ts` best-effort. События
      приватного пользователя видят только принятые друзья (как и
      библиотеку). Пагинации и ленты «весь GameHub» пока нет.
      В ленту также попадают события `REVIEWED` (F15) и
      `ACHIEVEMENT_UNLOCKED` (F12).
- [x] Отзывы (текст + оценка) — F15 (2026-09-06)
      Модель `Review` (оценка 1–10 + текст, один на пару пользователь+игра),
      блок на странице игры: свой отзыв редактируется сверху, чужие —
      списком. Отзыв привязан к записи `Game`, поэтому игра должна быть в
      базе (кто-то добавил её в библиотеку). `isHidden` — задел под
      модерацию, скрытые не показываются, UI-переключателя нет.
- Топы/подборки по рейтингу комьюнити — F20

## Этап 3 — Обогащение и геймификация (функции C)

- Скриншоты в отзывах — F17
- Достижения из внешнего API (если источник это поддерживает) — F11
- [x] Внутренние достижения GameHub — F12 (2026-09-06)
      40 бейджей, каталог в коде (`src/lib/achievements.ts`), таблица
      `UserAchievement` хранит только факт получения. Проверяются
      best-effort после действий с библиотекой и отзывами; бейджи на
      `/profile` (все, с прогрессом) и `/u/[username]` (только полученные).
      Два мета-бейджа («25 достижений», «все остальные») открываются в
      том же вызове через ограниченный fixed-point цикл. «Избранное»
      (#5/#6) считается по играм в коллекциях — отдельной фичи избранного
      нет.
- Лайки/комментарии к отзывам — F16
- Настройки приватности профиля — F4 (базовый флаг сделан на этапе 2;
  здесь — режим «только друзья» и приватность отдельных секций)
- Рекомендации игр на основе библиотеки/оценок — F19

## Явно не планируется в этой версии продукта

- Модерация/жалобы как отдельная система (только заделы в схеме).
- Мобильное приложение.
- Монетизация (см. открытые вопросы — статус не определён).

## Как читать этот roadmap

Каждый этап — самостоятельно демонстрируемый прирост ценности: после
этапа 1 уже есть работающий личный трекер игр, даже без единого
друга или отзыва. Этапы 2 и 3 можно менять местами или частично
совмещать в зависимости от того, что интереснее делать в первую
очередь.
